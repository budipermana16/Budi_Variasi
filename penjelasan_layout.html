Penting Untuk Presentasi Sidang

Web ini dibuat menggunakan konsep Single Page Application (SPA). Tidak seperti web multi-page tradisional yang memuat ulang seluruh halaman saat ganti menu, SPA hanya memuat ulang bagian konten (children) saja.

🔗 Bagaimana Laravel Berinteraksi dengan React?

Sistem ini dihubungkan oleh Inertia.js. Di dalam skripsi Anda, pastikan untuk menjelaskan alur ini kepada penguji:

  • Laravel bertindak murni sebagai Back-End (menyediakan routing, controller logika bisnis, kalkulasi ROP dengan Regresi Linear, dan database ORM Eloquent).
  • React (JSX) bertindak murni sebagai Front-End / User Interface yang bersifat dinamis dan reaktif.
  • Inertia.js adalah "Jembatan" (Adapter) yang mengirimkan data dari Controller Laravel ke komponen React dalam bentuk props tanpa perlu membangun API RESTful yang rumit.

Diagram Alur Request (SPA Router):

[Browser/Client]
  │ (mengklik link internal, misal /admin/products)
  ▼
[Inertia.js Link Interceptor]
  │ (mencegah browser melakukan reload halaman penuh, mengirim request AJAX khusus)
  ▼
[Laravel Back-End (Router & Controller)]
  │ (mengeksekusi logika, mengambil data produk, menghitung stok kritis)
  ▼
[Inertia Response (JSON payload)]
  │ (mengirim data produk balik ke client)
  ▼
[React Virtual DOM Update]
    (merender ulang bagian konten utama dalam AdminLayout secara instan)

Master Layout (Server-Side)

Kerangka dasar HTML pertama yang dimuat oleh server sebelum dialihkan sepenuhnya ke React.

📍 Lokasi & Detail File

Lokasi File:
resources/views/app.blade.php

Penjelasan:
Ini adalah satu-satunya file template Blade (HTML berbasis PHP) yang digunakan oleh aplikasi saat pertama kali diakses. Semua aset JavaScript dan CSS dideklarasikan di sini. Laravel hanya merender file ini satu kali, kemudian React mengambil alih siklus navigasi halaman berikutnya.

💡 Tip Sidang:
Jika dosen bertanya: "Di mana element root React di-mount?". Jawablah: "Di baris 12 menggunakan direktif @inertia, yang akan otomatis merender tag <div id="app"></div> di browser."
Blade Code app.blade.php 
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
    <head>
        <meta charset="utf-8">
        <meta viewport="width=device-width, initial-scale=1">
        <title inertia>{{ config('app.name', 'Laravel') }}</title>
        
        @viteReactRefresh
        @vite(['resources/css/app.css', 'resources/js/app.jsx'])
        @inertiaHead
    </head>
    <body class="font-sans antialiased bg-gray-50">
        @inertia
    </body>
</html>

⚙️ Penjelasan Detail Tag & Direktif

  • @viteReactRefresh: Menginstruksikan modul bundler Vite untuk bersiap melakukan Hot Module Replacement (HMR). Ini sangat berguna pada masa pengembangan agar perubahan code di React langsung ter-update di browser tanpa refresh manual.
  • @vite(['resources/css/app.css', 'resources/js/app.jsx']): Compiler aset dari Laravel Vite untuk memuat file CSS utama serta entry-point React aplikasi kita yaitu resources/js/app.jsx.
  • @inertiaHead: Digunakan untuk memuat metadata header halaman (seperti meta tag deskripsi, title dinamis yang disuntikkan dari komponen-komponen React individual menggunakan komponen <Head title="..." />).
  • @inertia: Merupakan server-side helper dari Inertia.js untuk merender container root SPA beserta JSON string payload data yang dikirimkan oleh Controller backend Laravel.

🛡️ Sistem Keamanan & Hak Akses (Role-Based)

Di dalam skripsi, aspek otorisasi adalah hal krusial untuk dibahas. Layout ini bertindak sebagai penjaga gerbang di sisi tampilan klien. Variabel currentUser?.role diperiksa untuk menampilkan atau menyembunyikan link menu:

Filter Group Menu Berdasarkan Role AdminLayout.jsx 
{/* Memfilter menuGroups berdasarkan role pengguna */}
{menuGroups
    .filter(group => group.roles.includes(currentUser?.role))
    .map((group, idx) => (
        <div key={idx} className="space-y-1">
            <p className="text-[10px] font-bold text-slate-500/80 uppercase">{group.title}</p>
            {group.items
                .filter(item => !item.roles || item.roles.includes(currentUser?.role))
                .map(item => <NavLink key={item.href} item={item} />)
            }
        </div>
    ))}
⚠️ Catatan Sidang (Sangat Penting!):
Jelaskan kepada penguji bahwa keamanan role-based di Front-End (React) ini hanya untuk menyembunyikan elemen UI. Keamanan yang sebenarnya (proteksi request data) dikelola di Back-End menggunakan RoleMiddleware.php di Laravel, sehingga admin gudang tidak akan bisa menembak URL milik owner meskipun merubah paksa tampilan React.

Layout Landing Page (Public-Facing)

Halaman utama toko Budi Variasi yang diakses oleh pelanggan publik secara langsung.

📂 Detail Lokasi File

Lokasi Layout & Halaman: resources/js/Pages/Home.jsx

Halaman ini berdiri sendiri (tidak dibungkus oleh AdminLayout) karena memiliki struktur desain publik yang berbeda (gelap bertema otomotif premium, animasi framer-motion, swiper slider, dan interaksi peta).

🧱 Struktur Bagian Utama Halaman

  • Sticky Navbar: Bar navigasi responsif yang menempel di atas halaman. Menyediakan akses cepat ke bagian Layanan, Galeri, Ulasan, Lokasi, dan tombol "Konsultasi Gratis" (WhatsApp).
  • Hero Section: Area sambutan utama yang elegan dengan background mobil berbayang gelap, menonjolkan keunggulan Budi Variasi sebagai bengkel variasi #1 di Ngawi.
  • Social Proof Banner: Memaparkan rating Google Maps secara dinamis (didapat dari database / google integration) untuk meningkatkan kredibilitas bisnis.
  • Interactive Photo Gallery: Carousel foto hasil pekerjaan yang dibuat menggunakan pustaka Swiper.js.
  • Services Grid: Kartu layanan dinamis (diambil dari database) yang diinput oleh admin/owner lewat dashboard admin.
  • Google Reviews Swiper: Slider ulasan asli pelanggan dari Google Maps.
  • Location & Map (Iframe): Menampilkan alamat fisik, jam operasional, dan peta interaktif Google Maps.
  • Floating WhatsApp Button: Tombol melayang di pojok kanan bawah untuk mempermudah calon pelanggan menghubungi toko secara langsung.

🎨 Desain Estetika Premium

Untuk memukau penguji sidang skripsi, jelaskan teknologi visual yang Anda terapkan pada file ini:

  • Framer Motion: Digunakan untuk animasi micro-interaction saat hover dan transisi yang halus sewaktu elemen masuk ke dalam layar (seperti fade-in-up dan stagger container).
  • Glassmorphism: Desain semi-transparan dengan efek blur latar belakang (backdrop-blur-xl bg-slate-950/80 border-b border-white/5) pada navigasi bar.
  • Glow Effect / Radial Gradients: Bola cahaya buatan dengan CSS radial-gradient dan filter-blur sebagai background dekoratif otomotif modern.
💡 Tip Pertanyaan:
"Bagaimana cara web mengambil data ulasan & foto Google?". Jawab: "Data ditarik dari database lokal (yang sebelumnya telah di-sinkronisasi dengan API Google Places / Maps) dan dilewatkan sebagai array props (services, testimonials, googlePhotos, googleRating) oleh LandingPageController."

Persiapan Mental & Materi

Bank Tanya-Jawab Sidang Skripsi (Layout & Arsitektur)

Daftar pertanyaan yang kemungkinan besar diajukan oleh dosen penguji terkait aspek pemrograman web ini, lengkap dengan jawaban akademis yang mantap.

1. Apa kegunaan utama dari file resources/views/app.blade.php? Bukankah aplikasi Anda menggunakan React?

Jawaban Akademis:
Meskipun front-end web ini menggunakan React, aplikasi ini tetap berbasis Laravel. File app.blade.php bertindak sebagai master layout server-side (HTML shell).

Saat pengguna pertama kali mengakses website, server Laravel akan merender file ini terlebih dahulu. Di dalam file inilah file bundle JavaScript React (app.jsx) dan Tailwind CSS dimuat melalui pustaka compiler Vite. Direktif @inertia di dalam body akan bertindak sebagai tempat kontainer root (mount point) di mana seluruh virtual DOM React dirender oleh browser.

2. Jelaskan bagaimana mekanisme pengiriman data dari database di Laravel ke layout React (misalnya nama user atau jumlah barang kritis)?

Jawaban Akademis:
Sistem ini menggunakan Inertia.js sebagai jembatan tanpa API. Proses pengiriman data terjadi melalui langkah berikut:
1. Di controller Laravel (misal DashboardController), kita memanggil Inertia::render('Admin/Dashboard', ['alertCount' => $count]).
2. Inertia akan menangkap data alertCount tersebut dan mengubahnya menjadi format JSON.
3. Di sisi front-end, Inertia mengumpankan data tersebut sebagai React Props langsung ke komponen halaman (Dashboard.jsx).
4. Komponen halaman kemudian meneruskan data props tersebut ke layout pembungkus (AdminLayout.jsx) sebagai properti layout.

3. Bagaimana sistem Anda membedakan tampilan menu sidebar antara Owner (Pemilik Toko) dan Admin Gudang? Di mana logikanya berada?

Jawaban Akademis:
Pembedaan tampilan menu dilakukan secara dinamis di file AdminLayout.jsx dengan memanfaatkan Role-Based Navigation Array.

Kami mendeklarasikan struktur menu di variabel menuGroups yang berisi objek menu beserta properti roles yang diizinkan (misalnya roles: ['owner'] untuk menu laporan perhitungan ROP).

Kemudian di dalam komponen React, sistem akan memfilter menu tersebut menggunakan fungsi .filter() javascript terhadap data user yang sedang login (diperoleh dari properti auth.user.role). Jika role user tidak ada di daftar hak akses menu, maka item menu tersebut tidak akan dirender ke DOM sidebar.

Tip Tambahan: Tambahkan penjelasan bahwa untuk mencegah bypass URL manual, rute di sisi server (back-end) juga diproteksi ketat menggunakan route middleware Laravel (misal Route::middleware(['role:owner']) di web.php).
4. Apa arti dari props {children} pada AdminLayout.jsx dan bagaimana cara kerjanya?

Jawaban Akademis:
Dalam React, children adalah properti bawaan (build-in props) yang mewakili elemen atau komponen anak yang dibungkus oleh komponen induk.

Pada AdminLayout.jsx, {children} ditempatkan di dalam tag <main class="flex-1 p-6">. Ini berarti, halaman apapun yang dibungkus oleh <AdminLayout> (seperti Dashboard.jsx, Products.jsx, dsb) akan dirender secara dinamis di area konten utama tersebut, sementara elemen luar seperti sidebar, header topbar, dan footer tetap statis. Ini menghemat penggunaan memory browser dan mempercepat waktu rendering halaman.

5. Mengapa sistem notifikasi barang kritis (alertCount) hanya ditampilkan kepada Owner, bukan Admin Gudang?

Jawaban Akademis:
Berdasarkan analisis kebutuhan sistem inventory control di Budi Variasi Mobil, wewenang pengambilan keputusan pemesanan barang kembali (Reorder) dan analisis finansial safety stock sepenuhnya berada di tangan Owner.

Oleh karena itu, notifikasi barang kritis (stok di bawah reorder point) hanya diarahkan ke Owner di dashboard dan sidebar agar Owner dapat segera menyetujui Purchase Order (PO) pembelian barang ke supplier. Sedangkan Admin Gudang berfokus pada operasional pencatatan barang masuk dan keluar fisik di gudang.

6. Mengapa halaman login (Login.jsx) dan landing page (Home.jsx) tidak dibungkus oleh AdminLayout.jsx?

Jawaban Akademis:
Karena kedua halaman tersebut memiliki tujuan fungsional dan desain estetika (layout grid) yang sepenuhnya berbeda:

- Home.jsx ditujukan untuk pelanggan eksternal (publik) yang memerlukan antarmuka visual bertema gelap-modern otomotif, integrasi ulasan Google Maps, galeri swiper, tanpa sidebar administratif.
- Login.jsx adalah gerbang keamanan satu halaman (standalone page) yang hanya berisi form otorisasi dan tidak memerlukan sidebar navigasi internal admin.

Oleh karena itu, masing-masing halaman merender layout uniknya sendiri-sendiri, sementara AdminLayout.jsx khusus didesain untuk halaman-halaman yang membutuhkan akses autentikasi internal.

  • Service Algoritma (Regresi Linear & ROP):
    app/Services/InventoryAlgorithmService.php

    app/Http/Controllers/Admin/PurchaseOrderController.php dan file layout pdf resources/views/pdf/purchase_order.blade.php.
    Digunakan untuk menjabarkan form surat PO ke supplier yang otomatis terisi data ROP barang tersebut.
